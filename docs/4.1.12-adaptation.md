## 1. 地址定位实战

### 1.1 pass1: addrfind 签名+组内 delta → 14/18

req2buf 全组、send、upload、uploadcb、startDownloadMedia 全部直出。
uploadImageAddr 是 reverse-hint(用 4.1.13 的 partial 反搜)拿到的, 31/32 唯一候选。

### 1.2 四个难键的本质(为什么静态难找)

`downloadFile/Imag/Video + uploadOnComplete` 是**函数体中段的回调分发点**
(非函数入口), 且三件套在 __DATA 零静态引用(chained-fixup 验证: rebase 位
bit63==0, 目标在低36位)——回调运行时注册进堆对象, IDA 交叉引用也找不到。
唯一出路 = 字符串锚定/结构字节匹配 + callscan 目视确认。

### 1.3 字符串锚定法实战要点

- 构建路径 `/Users/bkdevops/.wconan2/mmnet/<hash>/...` 的 `<hash>` 每次变,
  **路径串本体跨版本失配, 别当锚**; 用日志格式串(`cdntask %_ write last
  padding %_ bytes.`)/方法名(`OnRecvedData`)/断言文本
- 种子只用稀有串(全库出现 ≤8 次); mars::cdn/base64 表引用上千, 全局引用表
  必然截断, cap 永远轮不到真值点
- 串在 __cstring **任意对齐**, 别做 %4 检查(曾把 video 的锚全跳光)
- 每个旧拷贝×每个引用点都是独立种子(拷贝错位→预测平移)
- 验证用预测位置局部窗口反汇编看加载内容, 不建全局引用表; 簇评分=Σ不同锚
  各自最高分(跨锚互证)
- 结果精确度: file/video 精确到指令, imag 只到函数级(差 0x284, 函数重写幅度大)

### 1.4 结构字节匹配(uploadOnCompleteAddr 类)

虚调用块附近只有 "default" 等通用串, 锚定法无效。改搜已知指令序列字节:
`ldr x8,[x0]; ldr x8,[x8,#0x30]; mov x1,x19; mov x2,x21; blr x8` 在已知
邻近函数(uploadGetCallbackWrapperAddr)±0x4000 窗口 hexfind, 7 指令全等
唯一点 0x551e0e4。

### 1.5 addrfind 也会误配(必须 callscan 复核)

`uploadGetCallbackWrapperAddr`: addrfind 给了 0x551f644(不同 consumer,
签名恰好相似)。bl-caller 扫描 13-14 个调用点 + 4.1.11 对照实证正确位
=0x551da24。**工具产出一律当候选, 落 JSON 前必须语义确认。**

## 2. 结构/语义漂移清单(4.1.11 → 4.1.12)

| 项 | 4.1.11 | 4.1.12 | 备注 |
|---|---|---|---|
| 任务结构大小 | info ptr 0x2a0 | 0x2b8 (+0x18) | sendFunc 构造, 整块平移 |
| fileId / cdnUrl 偏移 | +0x2E0 / +0x2F8 | +0x2F8 / +0x310 | 随任务结构 +0x18 平移, task 指针 x19 |
| 本地落盘路径 | — | +0x328 | xwechat_files 下, DIAG 可见 |
| cndOnComplete 钥匙 | fileId/cdnKey/aesKey/md5/targetId 原偏移 | 整体 +0x08 | 逐字段 DIAG 实证 |
| videoId | +0xf0 (32-hex) | **字段消失** | 宽扫 0x00–0x260 无 32-hex; 传 "" proto3 省略, 服务端 ack 正常 |
| 下载三件套数据寄存器 | x22 | x21 | 寄存器分配漂移, hook 点取 bl 前一条 `mov x1,xN` |

## 3. 适配期崩溃与修复(指纹详见 crash-history.md)

| 类 | 现象 | 根因 | 修复 |
|---|---|---|---|
| A | 合成文本发送必崩, 栈顶落在 sendFunc 构造的任务结构被 delete/虚调用 | `triggerX1Payload` 是上次真实任务捕获的指针, 微信早已 free 毒化; +0x18 增长让残骸回调指针更野 | sendFunc 入口快照整块 0x300, 注入前 writeByteArray 恢复 |
| B | 用户 UI 手动发图即崩 SIGILL, 崩溃 PC 静态字节是不可能 SIGILL 的 `mov x0,x21` | discover 盲挂候选=改写运行时 __TEXT | 铁律: 静态优先, 只挂 callscan 确认点 |
| C | attach 报 "unable to intercept" 且中断同 setup 后续所有 hook | frida 不能挂 bl 指令 | 一律挂 bl 前一条 mov, 从 context 读数据寄存器 |
| D | 重构基址解析后首发送 ~1s 崩 Req2Buf 虚调用(FAR=0x10) | initAddresses 被同步提前调用, `var fakeVtable=ptr(0)` 初始化后行把全局重置回 0, 虚表指针=0 写进注入结构 | initAddresses 只能 setImmediate/回调异步派发 |
| E | onebot 日志正常但登录后零流量, hook 全挂空, 无报错 | "req2buf"字符串扫描竞态命中堆区 MallocHelperZone(>100MB rw-), 基址定到堆上 | 模块表优先(唯一 >50MB wechat.dylib), 字符串扫描兜底且校验可执行 |

教训: D 和 E 是同一次重构引入的一对坑(改基址解析必须两个改动一起回看);
A 的快照恢复机制后来成为 4.1.13 之前的标配。

## 4. structVer 版本开关(兼容机制)

- JSON 加 `"structVer": "2"` → script.js 走 4.1.12 布局(偏移平移/videoId 空/cndShift)
- 旧版 JSON 无此键, 模板渲染 `var structVer = "<no value>"` → 全部条件为
  false → 走 4.1.11 原路径, **老版本零变化, 零 Go 改动**
- 机制: main.go 把整个 config(`map[string]interface{}`)喂给 text/template,
  script.js 用赋值式 `var structVer = "{{.structVer}}"` 而非 `{{if eq}}`
  (缺键不报错, 只渲染成字符串)

  `ffmpeg -f lavfi -i testsrc=...` 合成; 视频同走 base64:// 且必须传 -image_path。
